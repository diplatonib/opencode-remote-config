# Contributing

Спасибо за интерес к проекту! Ниже — как внести вклад.

## Как сообщить о проблеме

- Баги: создайте [issue](https://github.com/diplatonib/opencode-remote-config/issues) с шаблоном баг-репорта — укажите версию opencode, шаги воспроизведения и ожидаемое поведение
- Предложения: используйте шаблон feature request
- Вопросы безопасности: **не** создавайте публичный issue — см. [SECURITY.md](./SECURITY.md)

## Настройка окружения

```bash
git clone git@github.com:diplatonib/opencode-remote-config.git
cd opencode-remote-config
npm install
npm test   # unit + e2e; внешняя сеть не требуется
```

Требования: Node.js >= 18. Подробности — [docs/DEVELOPMENT.md](./docs/DEVELOPMENT.md).

## Процесс работы

1. **Ветки** — создавайте feature-ветки от `main`: `feat/<name>` для функциональности, `fix/<name>` для багфиксов
2. **Коммиты** — [Conventional Commits](https://www.conventionalcommits.org/ru/): `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`
3. **Pull Request** — в `main`, с описанием что и зачем меняется; используйте шаблон PR и отмечайте чеклист
4. **Ревью** — изменения проверяются на корректность, тесты и соответствие стилю; правки по замечаниям добавляйте отдельными коммитами (squash выполняется при merge)

## Стандарты кода

- TypeScript, строгая типизация (`npm run typecheck` должен проходить без ошибок)
- Комментарии и строки документации — на русском языке
- Без лишних зависимостей: перед добавлением библиотеки убедитесь, что задача не решается stdlib или уже установленными пакетами

## Тестирование

- Любое изменение логики сопровождается тестами (unit — `tests/unit/`, интеграционные — `tests/e2e/`)
- E2E-тесты используют локальный mock-сервер — не добавляйте зависимостей от внешних сервисов
- Все тесты и typecheck должны проходить перед созданием PR
